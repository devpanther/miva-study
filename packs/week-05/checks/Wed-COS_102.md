# Wednesday — COS_102 nightly check

*What a flowchart is and what it is for, every flowchart symbol and its exact use, the four drawing principles, and the three control structures expressed as flowchart shapes.*
*Sit cold, notes closed, 8 minutes. Score out of 6.*

**1.** A team is drawing the flowchart for a monthly payroll run. Three of its boxes are: (i) a single box standing for the organisation's existing, separately documented tax-computation routine, which is not spelled out anywhere in this chart; (ii) a box showing that the staff records are held in the HR system; (iii) a box at the top marking off the machine set-up steps from the steps that actually carry out the payroll. Which three symbols, in that order?

a) Predefined process (declaration), database, preparation — the first shows a complex process or a well-known operation, the second shows where data is stored, the third shows the difference between steps preparing for work and those that actually work
b) Process (action), document, preparation — the first shows an action, process or function, and the second shows a document's input or output, the staff records being the document consumed
c) Predefined process (declaration), document, process — the second is a document because the staff records are read into the chart as input, and the third is a process because setting the machines up is itself an action
d) Preparation, database, predefined process — the tax routine is a preparation because it was prepared in advance of this chart, and the set-up boundary is a predefined process because both halves consist of well-known operations

**2.** A flowchart for a hospital admissions system has grown to three sheets. On sheet 1, the "insurance not verified" branch must resume at a box near the bottom of sheet 3. Separately, on sheet 1 alone, a branch must jump from the top-left of the sheet to a box at the bottom-right without dragging a flow line across the whole page. Which symbols, and why?

a) An on-page connector for the sheet-1-to-sheet-3 jump, because that branch stays inside one chart; a link connector for the jump within sheet 1, because it links two independent elements of the page
b) A link (off-page) connector for the sheet-1-to-sheet-3 jump, because it connects independent elements across multiple pages; an on-page connector for the jump within sheet 1, because it connects independent elements across a single page — and the second also serves the principle that flow lines should generally not cross
c) A merge symbol at both destinations, since in each case various paths are being combined into a single path, which is exactly what the merge symbol is for
d) A flow line in both cases. Connectors are labels for the reader and carry no flow of their own, in the same way as the comment symbol, so the real connection still has to be drawn as a line

**3.** Here is a flowchart written out box by box (`[ ]` terminator, `( )` process, `/ /` input/output, `< >` decision):

```
[ Start ]
    |
( Total = 0 )
( k = 0 )
    |
/ Enter mark /  <----------------------+
    |                                  |
< Is mark >= 50? >                     |
    | YES -> ( Total = Total + 1 ) --+ |
    | NO  --------------------------+ |
    |   (the two arms rejoin here)  | |
( k = k + 1 )  <--------------------+ |
    |                                  |
< Is k < 30? >                         |
    | YES ------------------------------+
    | NO
/ Print Total /
    |
[ Stop ]
```

Two diamonds appear. Which statement describes the control structures correctly?

a) Both diamonds are selections, since the diamond is the flowchart shape for selection; repetition is drawn with its own symbol, which does not appear here
b) The first diamond controls a repetition, because `Total = Total + 1` is executed many times over a run; the second is a selection, because it chooses between printing and carrying on
c) The first diamond is a selection — both arms go forward and rejoin before `k = k + 1` — while the second is the control point of a repetition, because its YES arm is a flow line back up to `Enter mark`; everything else is sequence
d) The two diamonds are the opening and closing of one repetition: the loop runs from the first diamond to the second, so `Enter mark` lies above the loop and is executed only once

**4.** A flowchart is handed in for review. It opens with a Start oval; it ends by simply running off the bottom of the page with no Stop oval; two of its flow lines cross once, at a point where the return line to the input box cannot avoid the outgoing line; its single decision box reads "Is the record valid and either the transaction date falls in the current quarter or an override flag has been set?"; and the boxes are drawn neatly and legibly. Assessed against the course's four principles, which verdict is right?

a) Two principles are broken — there is no stop point, and the comparison is not made as simple as possible and should be split into simpler decisions. The one crossing is not a breach, because flow lines should generally not cross *if possible*, and the chart is neat and clear
b) Three principles are broken — the missing stop point, the crossing flow lines, since flow lines must never cross, and the compound comparison
c) One only, the compound comparison. A stop point is optional in any chart whose flow returns to an earlier box, because such a chart has no single natural end
d) One only, the crossing flow lines. The missing stop point is covered by the connector convention, and comparisons of any complexity are permitted provided both arms are labelled YES and NO

**5. (explain why)** A project manager refuses to spend the afternoon on flowcharts: "we already have the pseudocode, the diagram only repeats it, and it will be out of date by Friday anyway." Answer him from the course. Give the two definitions of a flowchart the course provides, state the four reasons the course gives for needing flowcharts and the three advantages it lists, and then concede the three disadvantages it also lists — saying which of those three his "out of date by Friday" objection is actually naming, and why that concession does not defeat the case for drawing one.

**6. (explain why)** A student's flowchart for "read two numbers, add them, print the result" uses a rectangle for `Read N1 and N2`, a rectangle for `Print R`, a diamond for `R = N1 + N2`, and no ovals at all. Name the correct symbol for each of those three boxes, giving the course's definition and the alias for each, and say which drawing principle the missing ovals break. Then explain why a diamond is the wrong symbol for `R = N1 + N2` even though that box does determine the value of `R` — using what the course says the decision symbol is for, and how many arms leave it.

## Answers

**1. a** — *Predefined process, database and preparation: three symbols that all sit near the plain process box and are told apart by what the course says each is for.* The tax routine is **a complex process or a well-known operation** shown as one box, which is precisely the **predefined process** or **declaration symbol**; the HR system is **where data is stored**, which is the **database symbol** and the only symbol in the course's list whose definition contains the word *stored*; and the top boundary is the **preparation symbol**, which **shows the difference between steps preparing for work and those that actually work** — a definition that describes a boundary rather than an action, which is what makes it fit (iii). (b) uses **process** for the tax routine, which is the error of ignoring the word *predefined*: the process symbol **shows an action, process or function** that the chart itself spells out, whereas the whole point of (i) is that the routine is documented elsewhere and appears here as a single box. (b) and (c) both reach for **document**, whose stated use is to show **a document's input or output** — a document is a thing passing through the flow, not a place data lives, so it cannot express "held in the HR system". (c) then calls the set-up boundary a plain process, which loses the only distinction the preparation symbol exists to draw. (d) is the near-homophone trap and the commonest error here: *predefined* and *preparation* are not the same idea. *Predefined* means "defined outside this chart"; *preparation* means "before the real work begins". Swapping them produces exactly (d).

**2. b** — *On-page versus link (off-page) connector: identical purpose, distinguished only by whether the jump crosses a page boundary.* Both symbols are **used in complex flowcharts to connect independent elements**; the **on-page connector** does it **across a single page** and the **link or off-page connector** does it **across multiple pages**. Sheet 1 to sheet 3 crosses pages, so it is the link connector; top-left to bottom-right of sheet 1 stays on one page, so it is the on-page connector. The second choice also earns its keep against the principle that **flow lines should generally not cross, if possible** — a connector pair replaces a long line that would have to cross several others. (a) is the straight swap, and it is the wrong answer the Lesson I mid-lesson question is built to catch: "stays inside one chart" is not the criterion, "stays on one page" is. (c) confuses connecting with combining: the **merge symbol combines various paths into a single path**, so it belongs where two live branches join and continue as one, not where a single branch is being resumed after a break in the drawing. (d) generalises the **comment or note symbol** — which genuinely carries no flow and only **adds comments to parts of the flowchart** — to the connectors, which do carry flow; if they did not, complex multi-page charts would be undrawable and both symbols would have no reason to exist.

**3. c** — *Selection and repetition share the diamond; what tells them apart is where the arms go.* Follow the arms rather than the shape. The first diamond's YES arm runs through `Total = Total + 1` and its NO arm runs straight down, and **both rejoin before `k = k + 1`** — two forward arms meeting again is **selection**. The second diamond's YES arm is a flow line **back up to `Enter mark`**, a box already executed — an arm returning to an earlier box is **repetition**, and the loop is the second diamond together with everything between it and `Enter mark`. Every box outside those two constructs runs once in order: **sequence**. (a) is the "one shape, one structure" error: the course gives no separate loop symbol, which is exactly why you must read the arms; a diamond is *necessary* for both selection and repetition and *sufficient* for neither. (b) infers structure from how often a box happens to run rather than from where the flow lines go — `Total = Total + 1` runs many times because it sits inside the loop the *second* diamond closes, not because the first diamond is a loop. (d) is the most instructive wrong answer: it puts the loop's boundary at the first diamond, which would leave `Enter mark` outside the loop and read a single mark for all thirty passes. The return arrow lands **above** the first diamond, so the input box is inside the repetition — this is the one detail that decides whether the chart reads thirty marks or one.

**4. a** — *The four drawing principles, hedges included.* The course's principles are: **the flowchart should have a start point and a stop point**; **flow lines should generally not cross, if possible**; **instructions for comparisons should be made as simple as possible**; **the flowchart should be easy to follow, neat and clear such that the visual impact is very good**. Two are broken here. There is no stop point, and the first principle names both terminators, not just the start. And the decision box packs a conjunction and a disjunction into one comparison, which is not **as simple as possible** — it should become a short chain of simple decisions. The single crossing is not a breach: the principle is doubly hedged, **generally** and **if possible**, and here it is not possible. The chart is neat and legible, so the fourth principle holds. (b) hardens the flow-line hedge into a prohibition, which is the commonest misquotation of this slide and turns a preference into a rule the source does not state. (c) invents an exemption for looping charts; a chart whose flow returns to an earlier box still needs the exit branch of its decision to lead to a stop symbol, and a chart that can never reach one has an unterminated loop — the Week 4 characteristic of **finiteness** in graphical form. (d) is the mirror image of (b): it takes the one hedged principle as the only binding one and treats the two unhedged ones as optional, and it also misuses connectors as a substitute for a terminator — a connector resumes a flow elsewhere, it never ends one.

**5.** *Concept: what a flowchart is, the reasons the course gives for needing one, and the three advantages weighed against the three disadvantages the course itself states.* Start with the definitions: a flowchart is **a graphical representation of the sequence of operations in a computer program**, or equivalently **the graphical representation of an algorithm** — so it is not a rival to the pseudocode but the other member of the pair Week 4 named, **pseudocode or flowcharts**, and it **uses symbols to describe actions such as start/begin, stop/end, decision making and data processing** so that **complex processes can be quickly visualised**. The course gives four reasons we need flowcharts: they **provide clarity to program logic**; they **evaluate the actions resulting from setting some conditions** — which is exactly what pseudocode conveys least well, since a diamond with two labelled arms shows at a glance what follows from each answer; they **clarify a program's procedural steps**; and they **communicate the details of a program or process with other stakeholders**, the manager's own non-programmers included. Its three advantages follow: the **logic of a process or program is simplified**; the flowchart is used **to ascertain if the logic of the program works or not**, before code exists; and it is **added to the program specification documents such that other programmers can easily understand the logic of the program**. Now the concessions, which the course makes itself. **Complex programs or processes might require that the flowchart spans multiple pages** — the reason the link connector exists at all. **Adjustments to the flowchart might be complicated, and they might even require that a new flowchart is drawn** — and this is precisely what the manager's "out of date by Friday" is naming: not that the chart is useless, but that it is expensive to amend. **The flowchart logic is hardly the most efficient when used to write a program, because it can make the program unnecessarily longer than normal.** The concession does not defeat the case, because the three advantages are all cashed **before** the code is written — checking whether the logic works, and agreeing it with stakeholders, are cheapest at exactly the moment the manager wants to skip. A chart that is redrawn on Friday has already done its work on Wednesday.

**6.** *Concept: matching each operation to the symbol whose stated use fits it, and why the decision symbol is defined by its two arms rather than by "working something out".* `Read N1 and N2` is an **input/output** operation and takes the **input or output symbol**, **also called the data symbol**, which **shows data that can be used either at the input or the output**; a rectangle is wrong because the **process** or **action symbol** **shows an action, process or function**, and reading is data entering the chart, not work being done on it. `Print R` is the same symbol for the same reason — the one symbol serves both ends, which is why it is called the data symbol rather than the input symbol. `R = N1 + N2` is the box that genuinely **shows an action, process or function**, so it is the **process (action) symbol**, a rectangle — the student has the rectangles and the parallelograms exactly the wrong way round. The missing ovals are the **start/begin and stop/end symbol**, **also called the terminator symbol**, which **shows the start and end points of the flowchart**; omitting them breaks the first drawing principle, that **the flowchart should have a start point and a stop point**. As for the diamond: the **decision or control symbol** is **used when questions such as yes or no and true or false need an answer**, and **the answer to these questions determines the path the algorithm flow will take**. Both halves fail for an assignment. `R = N1 + N2` asks no yes/no or true/false question — it computes a value — and, decisively, nothing about the flow depends on it: whatever N1 and N2 are, the very next box is `Print R`. That is the structural test. A decision symbol has **one arrow in and exactly two arrows out**, each labelled with an answer, and it is the only symbol in the course's list with more than one exit; a box with a single exit cannot be a decision, however much arithmetic happens inside it. Drawing an assignment as a diamond also destroys the one thing the shape is good for — being able to see, at a glance, every point in the chart where the path can fork.
