# Saturday — COS_102 code nightly check

*Applying the strategies to stated problems: tracing a substitution puzzle, decomposing a target, choosing and justifying a strategy, and spotting where a strategy fails.*
*Sit cold, notes closed, 8 minutes. Score out of 6.*

**1.** Trace this substitution puzzle. The two rules are: replace **`OB`** with **`BOOB`**, and replace **`BOB`** with **`O`**. Starting from **`BOB`**, which sequence actually produces **`BOOOB`**?
a) `BOB → BOOB → BOOOB` — apply the first rule to the whole word, then again
b) `BOB → O → OB → BOOB → BOOOB` — shrink first, then rebuild
c) `BOB → BBOOB → BOOB → BOOOB` — grow by one rule, shrink, then grow again, never exceeding five letters
d) `BOB → BBOOB → BBOBOOB → BOOOB` — grow twice to seven letters, then apply the second rule

**2.** "There are 50 questions in an exam. 2 marks are deducted for every wrong response and 4 marks awarded for every correct response. Bridget scored 165 marks. How many correct responses did she provide?" A student sets `c + w = 50` and `4c − 2w = 165`, then tries every whole value of `c` from 0 to 50 and finds that none gives 165. What has this established?
a) Nothing yet; the search must be widened to allow unanswered questions, which will then produce a solution
b) `6c − 100 = 165` gives `c = 44.17`, so the answer is 44 correct responses — trial and error merely lost the fraction
c) Every attainable score `4c − 2w` equals `2(2c − w)` and is therefore even, while 165 is odd — so no combination of correct, wrong and unanswered responses can score 165; the trials exhausted the candidates without ever explaining why, whereas one abstraction settles it at once
d) The trial-and-error run failed only because 51 candidates is too many for the method; on a shorter exam the same approach would have worked

**3.** XYZ Corporation's product quality is declining. Engineering lists 26 candidate causes across the manufacturing line. A junior proposes altering one input at a time and shipping a production batch after each change to see whether quality recovers. Judge this against the course.
a) It is a good plan: trial and error recognises and removes errors through experimental trials, which is exactly what a quality problem needs
b) It is trial and error applied where the number of possible solutions is **not** few, so it is time-consuming and inefficient; the case study instead begins with **root cause analysis** to identify the manufacturing process issues, narrowing the candidates before anything is changed
c) It is heuristics, and heuristics is barred from quality work because its solutions are not always rational; the case study begins by forming a cross-functional team
d) It is a poor plan because trial and error can never remove an error once introduced; the case study begins with brainstorming

**4.** A student is asked to write a program **H** that takes any program **P** plus P's input, prints YES if P eventually halts on that input, and NO if P runs for ever. He plans to have H simply run P and print YES the moment P stops. Which is correct?
a) The plan is sound and only needs enough memory and a fast enough machine to be practical
b) This is a non-routine problem, so the student must develop a novel method by studying the problem critically, gathering information and implementing an effective strategy
c) The halting problem is **undecidable** — no algorithm returns an accurate true/false for **every** input value — and the student's plan never prints NO at all, so it does not decide the question; it is not a systematic method
d) The halting problem is unsolvable, meaning no program's halting behaviour can ever be determined, so H cannot be written and no individual P can be judged either

**5. (explain why)** A student must complete a degree syllabus of 8 courses, each carrying 12 weeks of material, in **6 months**, while working 20 hours a week. Set this out as **means-ends analysis** would: state the target, at least three sub-problems the decomposition produces, and for each sub-problem the approach you would pick. Then state the one requirement means-ends analysis adds that "just break it into pieces" does not.

**6. (explain why)** An online store's checkout fails for roughly 1 user in 500; the cause is unknown and the team has drawn up 40 candidate causes. A junior engineer proposes disabling one feature at a time in production until the failures stop. A senior engineer says "it is always the payment gateway — start there." Evaluate each proposal against the course's stated condition for its strategy, say what each risks, and explain how **abstraction** could make the junior's method viable.

## Answers

**1. d** — *Tracing a substitution puzzle; a derivation may have to grow before it shrinks.* Take it one rule application at a time. `BOB` contains exactly one `OB` (letters 2–3), so rule 1 gives `B` + `BOOB` = **`BBOOB`**. In `BBOOB` the only `OB` is letters 4–5, so rule 1 gives `BBO` + `BOOB` = **`BBOBOOB`**. Now letters 2–4 of `BBOBOOB` are `B,O,B`, so rule 2 replaces them with `O`: `B` + `O` + `OOB` = **`BOOOB`**. (a) misreads rule 1 as licensing `BOB → BOOB`; the rule rewrites the substring `OB`, not the whole word. (b) dies at the first step: `BOB → O` is legal, but a lone `O` contains neither `OB` nor `BOB`, so nothing can ever be applied to it again — a dead end. (c) is the answer that catches anyone who assumes a derivation should never overshoot the target length: `BBOOB → BOOB` deletes a `B`, and **no rule deletes a single letter**. That "grow past the target, then collapse" step is exactly why there is no systematic method for deciding whether an arbitrary substitution puzzle comes out — nothing bounds how far the string may have to grow first.

**2. c** — *Abstraction succeeding where trial and error can only exhaust.* Every correct response adds 4 and every wrong one subtracts 2, so any attainable score is `4c − 2w = 2(2c − w)` — always **even**. 165 is odd, so it is unattainable, and this holds whether or not every question was answered. (a) is the natural next move and still fails, because relaxing `c + w = 50` changes nothing about parity — the mark to notice is that the constraint the student relaxed was never the binding one. (b) is the arithmetic-slip answer: `6c − 100 = 165` really does give `c = 44.17`, and rounding a non-integer into an answer is precisely the error the exhaustive trials should have warned against. (d) misapplies the course's rule about trial and error: 51 candidates *is* few, so the method was legitimately applicable — it simply returns "none of these" without ever supplying the reason, which is its true limitation here. Trial and error can only report the outcome of the trials it ran; abstraction, by filtering the problem down to the single relevant attribute (the parity of the score), yields the reason in one line.

**3. b** — *Strategy fit judged by the course's condition, not by the definition.* The junior's plan matches the **definition** of trial and error perfectly, which is what makes (a) so tempting — but a strategy is chosen by its **condition**, and the course states that trial and error is time-consuming and inefficient when the number of possible solutions is not few. Twenty-six candidate causes, each costing a full production batch to test, is the textbook case of "many". The case study's methodology begins with **root cause analysis** to identify the manufacturing process issues, then analyses customer feedback, quality records and production reports, and forms a cross-functional team — all of which shrink 26 candidates to a few before any change is made. (c) invents a prohibition the course never states and misnames the strategy: nothing here is decided without thinking. (d) contradicts the definition of trial and error, whose whole point is recognising and removing errors through trials.

**4. c** — *Decidable vs undecidable, and what "unsolvable" does not mean.* An undecidable problem is one for which **no algorithm can give an accurate true/false for every input value**, and the halting problem is the course's named example. The student's plan is not merely slow, it is not an algorithm for the problem at all: on a program that never halts it never returns, so the NO branch is unreachable and no answer is ever produced. (a) is the "just add hardware" error — the obstacle is not resources but that no systematic method exists. (b) is the sharpest distractor, because it is a true-sounding sentence about a **different** category: a **non-routine** problem merely lacks a *standard* method, and originality can supply one; an **undecidable** problem admits no method however creative the solver. Confusing the two is the week's central trap. (d) is the misreading the course explicitly warns against: "unsolvable" does not mean no solution can possibly be found — plenty of individual programs can be shown to halt or loop; what fails is the existence of a general deciding procedure.

**5.** *Concept: means-ends analysis — decomposition plus a chosen approach per sub-problem.* **Target:** 96 course-weeks of material covered and assessed within 26 calendar weeks, alongside 20 paid working hours a week. Means-ends analysis begins by thinking about the solution beforehand and identifying the issues that will be encountered — here, a roughly 4:1 compression of material, a fixed weekly time budget, and eight assessments to pass. The decomposition might run: **(i) Time budget** — establish how many study hours per week actually exist after 20 working hours; approach: arithmetic scheduling, a routine sub-problem solved with a straightforward algorithm. **(ii) Material triage** — decide which of the 96 course-weeks are load-bearing and which are supporting detail; approach: **abstraction**, filtering out material that will not contribute to passing so a model of the syllabus remains. **(iii) Sequencing** — order the eight courses so prerequisites come first and assessment deadlines are met; approach: dependency ordering, a solvable problem naturally expressed as a graph. **(iv) Recovery** — decide in advance what happens in a week that is lost to work; approach: **heuristics**, since a fast, good-enough rule beats a perfect but late plan. **The requirement means-ends analysis adds:** it is not enough to split the problem — each smaller problem must be **solved with the best possible approach**, chosen in advance from the issues expected to arise, and every sub-problem must be solved, because it is the solving of all of them that solves the main problem. Plain decomposition stops at the split; means-ends analysis is answerable for the method attached to each piece and for the target the pieces must close.

**6.** *Concept: matching a strategy to its stated condition; abstraction as a precondition for trial and error.* The junior is proposing **trial and error**, whose condition is that the **number of possible solutions be few**. With 40 candidate causes, and a fault that shows only once in 500 checkouts, it is squarely in the case the course calls **time-consuming and inefficient**: each trial needs enough traffic to be sure the failure has really stopped rather than merely not recurred yet, so 40 trials could take months — and disabling live features risks introducing new failures that contaminate the very signal being measured. The senior is proposing **heuristics**, whose condition is that a **sub-optimal solution be acceptable** and whose payoff is saving time and energy by deciding **without stopping to think about the next course of action**; the course also warns that such solutions are **not always rational**. The risk is exactly that: if the gateway is innocent, the team has spent its effort on a confident guess and has learned nothing that narrows the remaining 39 causes. Neither is wrong as a strategy; each is being asked to work outside its condition. **Abstraction** repairs this by changing the number the condition depends on: filter out every attribute of the failing sessions that cannot bear on the fault — browser chrome, page styling, user names — and keep what might (payment method, cart size, currency, network region, whether the session was resumed). The resulting model of "which sessions fail" typically eliminates most of the 40 candidates at a stroke. Once the candidate set is genuinely **few**, trial and error becomes the right instrument, and the senior's rule of thumb becomes what it should have been all along — one hypothesis inside that small set rather than a substitute for narrowing it.
