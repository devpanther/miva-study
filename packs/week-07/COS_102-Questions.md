## Section A — Multiple choice (12)

**1.** Why should a count of students be held in an `int` rather than a `float`?
a) A `float` cannot hold a whole number, so the count would be corrupted immediately
b) An `int` occupies less memory than a `float` on every machine, so counters should always be `int`
c) An `int` is exact within its range, whereas a `float` stores an approximation to a fixed number of significant digits, so values accumulated in a `float` can drift away from the true count
d) Arithmetic on a `float` is not permitted inside a loop condition, so a `float` counter could not be tested

**2.** What does the line `extern int total;` do?
a) It defines `total` and initialises it to 0
b) It reserves storage for `total` and forbids its value from being changed afterwards
c) It defines `total` but restricts its visibility to the function in which it appears
d) It declares `total` — name and type only — without reserving any storage, so the storage must be defined in exactly one place elsewhere

**3.** A student writes `if (x < y < z)` intending to test that `y` lies between `x` and `z`. What actually happens?
a) It parses as `(x < y) < z`, because relational operators associate left to right, so a 1 or a 0 is compared with `z` and the test almost never means what was intended
b) It parses as `x < (y < z)`, because relational operators associate right to left
c) It is a syntax error, because a relational operator may not take another relational expression as an operand
d) It correctly tests whether `y` lies between `x` and `z`; C permits the chained form for exactly this purpose

**4.** With `int a = 5, b = 2;`, which expression has type `double` **and** value 2.5?
a) `a / b`
b) `a / 2.0`
c) `(double)(a / b)`
d) `a % b`

**5.** A single keypress has been read into `char c`, and the program needs the numeric value of the digit that was typed. Which line does it, and for the right reason?
a) `int d = c;` — assigning a `char` to an `int` yields the number the character displays
b) `int d = atoi(c);` — `atoi` is the standard conversion from a character to its numeric value
c) `int d = c % 10;` — the remainder on division by 10 extracts the digit from the character code
d) `int d = c - '0';` — `c` holds the character's code, and the codes of `'0'` to `'9'` run consecutively, so subtracting the code of `'0'` gives the digit's value

**6.** With `int x = 1, y = 2;`, what are the values of `x & y` and `x && y`?
a) 0 and 1
b) 1 and 1
c) 3 and 1
d) 0 and 0

**7.** `if (n != 0 && total / n > 5)` is safe; `if (total / n > 5 && n != 0)` is not. Why?
a) The compiler is free to reorder the operands of `&&` to put the cheaper test first, so in practice both versions behave identically
b) Division by zero yields 0 in C, so both versions are safe and the first is merely clearer
c) The order of the operands of `&&` makes no difference; only the order of the `if` and `else` branches matters
d) `&&` evaluates its right operand only when the left one is true, so the first version never performs the division when `n` is 0, while the second performs it before the guard has been tested

**8.** Which statement is true?
a) Renaming a variable from `t` to `temperature` throughout the source makes the compiled program use more memory while it runs
b) The compiler stores each variable's name next to its value, so that the running program can look the variable up when it needs it
c) Variable names are not stored inside the computer memory — the compiler replaces them with memory location addresses — so a consistent rename changes nothing about what the compiled program does
d) Names are stored in memory for global variables only, which is why a global is slower to reach than a local

**9.** A `LibraryBook` class keeps `copiesOut` **private** and publishes the methods `borrow()` and `returnBook()`. What does making the variable private actually buy?
a) A `private` variable occupies less memory than a `public` one, so a class with private state is cheaper to use
b) A `private` variable cannot be changed once it has been set, which removes a whole class of errors
c) Because only the object's own methods can reach the variable, every change to it passes through code that can enforce the rules — never below zero, never above the number owned; make it public and any part of the program can set it to anything, and the object can no longer guarantee its own state
d) A class will not compile unless at least one of its variables is declared `private`

**10.** A record must hold a student's matriculation number, name and CGPA at the same time. Structure or union?
a) A union, because it groups items of possibly different types into a single type while using less memory
b) A structure, because a union variable can represent the value of only one of its members at a time, and this record needs all three at once
c) Either will do, since the course defines both as a user-defined data type that can be used to group items of possibly different types into a single type
d) A class, because only a class can hold three members of different types

**11.** What does `int i = 0; while (i = 5) { … }` do?
a) The body runs exactly five times, after which `i` reaches 0 and the loop ends
b) The body never runs, because `i` was initialised to 0
c) The loop runs for ever: the condition **assigns** 5 to `i` and yields 5, which is non-zero and therefore true at every test
d) The compiler rejects the condition, because an assignment may not be used where a truth value is expected

**12.** On a machine where `int` occupies 4 bytes and must start at an address that is a multiple of 4, what are the sizes of `struct S { char a[10]; int b; };` and `union U { char a[10]; int b; };`?
a) `sizeof(struct S)` is 14 and `sizeof(union U)` is 10 — the structure is the sum of its members and the union is its largest member
b) `sizeof(struct S)` is 16 and `sizeof(union U)` is 12 — the structure pads `a` out so that `b` begins on a 4-byte boundary, and the union takes the size of its largest member rounded up to the same boundary
c) `sizeof(struct S)` is 14 and `sizeof(union U)` is 14, since a union must be able to hold all of its members
d) `sizeof(struct S)` is 16 and `sizeof(union U)` is 16, since a union must be the same size as the structure with the same members

## Section B — Short answer (3)

**13.** A program computes `float avg = sum / count;` where `sum` and `count` are both `int`. Set out what the machine does, step by step, and say at which step the fractional part is lost. Give **three** different one-line ways of obtaining a correct fractional average, saying for each exactly where the conversion enters. Then explain why this bug so often survives testing — use the lecture's own example, the average of the first five multiples of 9, to show it.

**14.** Take this condition: `total > 0 && sum / total >= pass_mark || override`. State the order in which the operators are applied and why. Say what is guaranteed **not** to be evaluated when `total` is 0, what rule guarantees it, and what would happen without that guarantee. Then rewrite the condition with every implied bracket written in, and say how the meaning would change if `||` bound more tightly than `&&`.

**15.** Using the course's dog example, explain how a real-world object's **state** and **behaviour** become parts of a programme object. Then state what a **structure**, a **union** and a **class** each give you, and choose the right one for each of these, justifying the choice: (i) a record of a book's title, author and number of copies; (ii) a sensor reading that is either an `int` count or a `float` voltage but never both at once; (iii) a bank balance that must never be set directly by code outside the account.

## Answers

**1. c — An `int` is exact within its range; a `float` is an approximation.** *Concept: exactness versus range.* A `float` keeps a sign, an exponent and a fixed number of significant digits, so most values are stored as the nearest representable one; counting is the one job where "nearest" is not good enough, and repeated addition lets the error accumulate. (a) is false — a `float` holds whole numbers perfectly well up to the point where its significant digits run out; that is exactly why the problem is hard to see. (b) is false in fact: `int` and `float` are both typically 4 bytes. (d) is invented; a `float` may appear in any condition.

**2. d — A declaration that is not a definition.** *Concept: declaration vs definition.* `extern` says: an `int` named `total` exists, defined elsewhere; check my uses of it against that type, and reserve nothing. This is the "not all variable declarations are definitions" half of the slide's rule, and it is what lets several separately-compiled files share one variable. (a) confuses declaration with initialisation — and `extern` initialises nothing. (b) confuses `extern` with `const`. (c) has it backwards: `extern` is about widening visibility across files, not narrowing it.

**3. a — `(x < y) < z`.** *Concept: associativity within one precedence level.* Both `<` operators sit at the same level, and that level associates left to right, so the first comparison happens and yields the `int` **1** or **0**; that 1 or 0 is then compared with `z`. With `x = 1, y = 5, z = 3` the intended test is false but the expression gives `(1 < 5) < 3` = `1 < 3` = **true**. (b) gets the associativity backwards — right-to-left belongs to the unary operators, `?:` and assignment. (c) is wrong because a relational expression is an ordinary `int`-valued expression and may be an operand anywhere. (d) is the mathematical reading the student had in mind, which is what makes the error invisible; the correct C is `x < y && y < z`.

**4. b — `a / 2.0`.** *Concept: the operand types choose both the operation and the result type.* `2.0` is a `double` literal, so `a` is converted to `double` and a floating-point division is performed: 5.0 ÷ 2.0 = **2.5**, type `double`. (a) has two `int` operands, so it is an integer division: value 2, type `int`. (c) does the same integer division first and only then widens the 2 to 2.0 — right type, wrong value, and the classic "cast in the wrong place" error. (d) is the remainder, `5 % 2` = 1, type `int` — right that it is not 2.5, but it is not even a division.

**5. d — `int d = c - '0';`** *Concept: a digit character and the number it denotes are different values.* `c` holds the character's code — `'7'` is 55 — and the standard guarantees that the codes for `'0'` to `'9'` are consecutive, so subtracting the code of `'0'` (48) leaves the digit's value. (a) is the assumption the whole trap rests on: it copies the code, so `d` would be 55, not 7. (b) confuses a `char` with a **string**: `atoi` takes a pointer to a null-terminated array of characters, so passing a single `char` is a type error, not a conversion. (c) happens to give 5 for `'7'` and is arithmetic performed on the code for no reason; it works for no digit at all.

**6. a — 0 and 1.** *Concept: bitwise versus logical.* `x & y` pairs the operands bit by bit: `0001 & 0010` has no bit set in both, so it is **0**. `x && y` asks whether both operands are non-zero; 1 and 2 both are, so it is **1**. This single example is the cleanest proof that the two operators are not interchangeable. (b) treats `&` as `&&`. (c) computes `x | y` = 3, confusing AND with OR. (d) treats `&&` as if it too worked bit by bit.

**7. d — Short-circuit evaluation.** *Concept: `&&` skips its right operand when the left is false.* The guard only guards if it is evaluated **first**: in `n != 0 && total / n > 5`, a zero `n` makes the left operand false and C guarantees the right operand is not evaluated, so the division never happens. Reversed, the division is the left operand and runs unconditionally — dividing by zero, which is undefined behaviour and typically crashes. (a) is the dangerous belief that the compiler may reorder; it may not, the evaluation order of `&&` is fixed by the language, which is precisely why the idiom works. (b) invents a value for division by zero. (c) confuses the operands of an operator with the branches of a statement.

**8. c.** *Concept: names are compile-time, addresses are run-time.* The compiler turns every use of a name into an address; nothing of the name survives into the ordinary compiled program. So names may be as long and as descriptive as you like at no run-time cost, and a consistent rename produces the same machine code. (a) is the direct contradiction of the course's statement and the reason students give for cryptic names. (b) describes a debug symbol table, which is added for the *debugger*, not so that the program can find its own variables. (d) invents a locals/globals distinction; the difference between them is where the storage lives and how long it lasts, not whether a name is stored.

**9. c.** *Concept: encapsulation as enforcement, not as concealment.* The course's statement is that **only the methods of a particular object have access to the variables of that object**. That turns the methods into the only door, and a door can be given a lock: `borrow()` can refuse when no copies remain, `returnBook()` can refuse to push the count above the number owned. A public variable has no door, so no rule about it can be enforced — any line anywhere may set it to −4 — and the object's guarantees become promises the compiler cannot keep. (b) is the commonest wrong answer and confuses `private` with `const`: a private variable is changed constantly, just only from inside. (a) invents a memory cost; access specifiers are compile-time only. (d) invents a language rule.

**10. b — A structure.** *Concept: struct vs union is about simultaneity, not about types.* The deciding fact is that **all of a union's members start at the same location in memory**, so **a union variable can represent the value of only one of its members at a time**; writing the name would destroy the matriculation number. A record whose fields must coexist has to be a structure. (c) is the trap for anyone who looked for the difference in the definition wording: "groups items of possibly different types into a single type" is said by the course of **both**, so it cannot separate them. (a) picks the union for the memory saving and ignores what the saving costs. (d) is false: a structure holds members of different types perfectly well — what a class adds is **methods** and access specifiers, not mixed types.

**11. c — It runs for ever.** *Concept: `=` is an assignment expression with a value.* `i = 5` stores 5 in `i` and the expression's own value is the value stored, 5. A condition is true whenever it is non-zero, so the test succeeds; and because the assignment is re-executed on every pass, `i` is reset to 5 each time and nothing inside the body can ever change the outcome. (a) reads the condition as `i < 5` or as some kind of countdown; nothing here counts. (b) reads it as `i == 5` and evaluates that against the initial 0 — the intended code, and the reason the typo is so hard to see. (d) is wrong for the reason that makes this dangerous: the construct is entirely legal, and a compiler is permitted only to warn.

**12. b — 16 and 12.** *Concept: structures lay members out side by side and pad for alignment; unions overlay them.* In the **structure**, `a` occupies offsets 0–9; `b` must begin on a multiple of 4, and the next such offset is 12, so bytes 10 and 11 are padding, `b` occupies 12–15, and the total is **16**. In the **union**, every member starts at offset 0; the largest is `a` at 10 bytes, but the whole object must still be aligned for its `int` member, so 10 is rounded up to the next multiple of 4, giving **12**. (a) is the naive arithmetic — sum for the struct, largest member for the union — right in outline and wrong because it ignores alignment; it is the answer to memorise the *shape* of and then correct. (c) treats the union as having to hold everything at once, which is the definition of the structure. (d) assumes a union costs the same as the equivalent structure, which would leave it with no purpose at all.

**13.** *Concept: integer division, the moment of conversion, and why the bug hides.* **What the machine does.** First it looks at the operands of `/`. Both `sum` and `count` are `int`, so the usual arithmetic conversions leave them alone and the compiler selects the **integer division** instruction. That instruction computes the quotient and truncates towards zero — **this is the step at which the fractional part is lost**, and it is lost irrecoverably, before anything else in the statement happens. The `int` result is then converted to `float` and stored in `avg`. The type of `avg` had no influence on any of it, because C chooses an operator's meaning from the **types of its operands**, which are settled before the assignment is considered. **Three fixes.** (i) `float avg = (float) sum / count;` — a cast is a unary operator and binds tighter than `/`, so it applies to `sum` alone; one operand becomes floating, the other is promoted to match, and a floating-point division is performed. (ii) `float avg = sum / (float) count;` — the same thing from the other side. (iii) `float avg = sum / (count * 1.0);`, or `sum / 5.0` where the divisor is a literal — the conversion enters through a floating **literal** rather than a cast. In every case the conversion must reach an **operand**; `(float)(sum / count)` is not a fix, because the brackets put it on the *result*, after the truncation. **Why it survives testing.** Because integer division is only visibly wrong when the division is inexact, and the natural first test case is usually exact. The lecture's own example is the perfect illustration: the first five multiples of 9 are 9, 18, 27, 36 and 45, so `sum` is **135** and `count` is 5, and `135 / 5` is **27** exactly — integer division and real division agree, the program prints 27.000000, and the test passes. Change it to the first **four** multiples: `sum` is 90, `count` is 4, the true average is **22.5**, and the buggy line prints **22.000000**. The error is not a crash, not a wild number, but a plausible value half a mark low — so it passes review as well as it passed testing.

**14.** *Concept: precedence across arithmetic, relational and logical operators, plus short-circuit evaluation as a safety device.* **Order of application, and why.** The precedence ladder fixes it: `*` and `/` bind tightest of the operators present, then `+` and `-`, then the relational `>` and `>=`, then `&&`, then `||`. So the machine first evaluates `sum / total`; then the two comparisons, `total > 0` and `sum / total >= pass_mark`, each yielding 1 or 0; then the `&&` of those two; and last the `||` with `override`. **What is skipped when `total` is 0.** `total > 0` is false, so `&&` — which can only be true if both operands are true — already knows its answer, and the rule of **short-circuit evaluation** guarantees that its right operand `sum / total >= pass_mark` is **not evaluated at all**. The division therefore never happens. Without that guarantee the program would divide by zero, which is undefined behaviour and in practice a crash or a nonsense result; the whole idiom of writing the guard to the left of `&&` exists because the guarantee exists. Note what is *not* skipped: `override` is the right operand of `||`, and `||` short-circuits only when its **left** operand is true — here the left operand is 0, so `override` is evaluated and can still make the whole condition true. **Fully bracketed:** `((total > 0) && ((sum / total) >= pass_mark)) || override`. **If `||` bound more tightly than `&&`** the same characters would read `(total > 0) && (((sum / total) >= pass_mark) || override)`, which is a different condition: `total > 0` would become **compulsory**, so an `override` could no longer rescue a record with no entries at all, whereas in the real reading `override` alone is enough to make the condition true. Both readings happen to be safe from division by zero — in the mis-bracketed one the `&&` still short-circuits on `total > 0` — but they accept different data, which is exactly why the precedence of `&&` above `||` has to be known rather than assumed.

**15.** *Concept: state and behaviour as variables and methods, and choosing between structure, union and class.* **State and behaviour.** **Real-world objects have two main characteristics: state and behaviour.** The dog's state is its *name, colour, breed* and whether it is *hungry*; its behaviour is *barking, fetching, wagging its tail*. In a programme object the mapping is exact: **the state of an object is stored in variables and the behaviour of objects is described by methods**, and **every object has its own variables and methods** — two dogs have two `name` variables, not one shared between them. The restriction that makes it worth doing is that **only the methods of a particular object have access to the variables of that object**, and **different objects can only interact with each other through their own individual methods**; that is information hiding, and it is what lets the author **control the amount of information shared about the object with the outside world**. **What each construct gives you.** A **structure** (`struct`) is a user-defined type grouping items of possibly different types into a single type; every member has **its own storage**, so all members hold values at once, and members are reached with the **dot syntax**. A **union** (`union`) is written the same way and groups the same kind of members, but **all of them start at the same location in memory**, so it holds **one member at a time** and occupies the size of its largest member. A **class** is like a structure but **also has methods or functions**, together with access specifiers (`public`, `private`) that decide who may reach which members. **The three choices.** (i) *Book title, author and copies* — a **structure**. The three values must coexist: a book has a title *and* an author *and* a count, and in a union the second `strcpy` would obliterate the first. There is no behaviour to attach and nothing to protect, so a plain `struct` is exactly right. (ii) *Either an `int` count or a `float` voltage, never both* — a **union**. This is the case unions exist for: the two readings are **alternatives**, so overlapping them costs nothing in correctness and saves the space of the smaller one. In practice the union should be wrapped in a **structure** together with a small tag variable recording which member is currently live, because the union itself does not remember, and reading the member that was not written last gives one member's bytes reinterpreted as the other's type. (iii) *A bank balance that may not be set directly from outside* — a **class**, with the balance `private` and `deposit()` and `withdraw()` `public`. Neither a structure nor a union can do this, because both expose their members to any code holding the variable; only the class carries methods and access specifiers, so only the class can make every change to the balance pass through code that checks it. This is **data encapsulation** — *hiding the implementation details of an object from the user, so that the user can only interact with the object through a set of public methods while the internal workings remain hidden* — and it is the reason the course lists modularity, code reusability and the independence of objects among the benefits of object-oriented programming.
