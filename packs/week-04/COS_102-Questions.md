## Multiple choice

**3.** In the algorithm development process, which step comes immediately after high-level algorithm development?

**4.** A client asks for "a report listing the busy staff" but never says what counts as busy. Which Step 1 issue is this?

**5.** Which statement is true of priori analysis?
a) It measures the actual running time of the code once it has been executed on a machine.

**6.** A loop whose loop variable is divided by a constant amount on each pass has time complexity:

## Short answer

**13.** Name the five algorithm development steps in order, and state precisely what distinguishes Step 3 from Step 4.

**14.** A classmate says: "Big O tells you how many seconds an algorithm will take." Explain what Big O actually describes, and use the 1000N versus N² example to show why their statement is wrong.

**15.** Write the refined pseudocode from the lecture for determining the maximum of a set of numbers entered by a user, and state which of sequence, selection and repetition it uses.

## Answers

**1. b** — An algorithm is a plan for solving a problem, designed by people; a program is the instruction set the computer follows, and the algorithm must be converted into one.
**2. c** — The deck states algorithms consist of inputs, a process, and outputs; sequence/selection/repetition are the *representation* forms, not the components.
**3. d** — The order is description → analysis → high-level development → refinement → review.
**4. a** — "Busy" has no agreed meaning, so the description can be read more than one way: that is ambiguity, not omission.
**5. b** — Priori analysis is pre-implementation and language-independent, and so does not directly affect the implementation; posterior analysis is the one that deals with actual space and running time.
**6. c** — A loop variable divided (or multiplied) by a constant amount gives O(log n); incrementing or decrementing by a constant gives O(n).
**7. d** — Worst case is the maximum time for an input of size n; the minimum is best case and the typical input is average case.
**8. a** — The same step is executed repeatedly for each employee, which is exactly what repetition (while condition is true, do) is for.
**9. b** — Big O compares growth rate, not values at small n: N² eventually overtakes 1000N, so the N² algorithm is less efficient.
**10. c** — The stated rule for O(n^c) is that nested-loop complexity equals the number of times the innermost statement is executed.
**11. d** — Algorithms should not be dependent on any programming language; that characteristic is language independence.
**12. a** — The deck states we need algorithms for reasons such as performance and scalability; the others are design considerations or measures, not the reasons given.

**13.** Step 1 Problem description, Step 2 Problem analysis, Step 3 High-level algorithm development, Step 4 Algorithm refinement, Step 5 Algorithm review. Step 3 deliberately covers only the main parts of the solution and omits every minor detail, because chasing detail before you have any solution is time-wasting and costly. Step 4 (stepwise refinement) adds the detail to each high-level step, decided by who will implement the algorithm, how much knowledge that person has, and the computer specifications.

**14.** Big O describes the **growth rate** of an algorithm — how the time or space requirement grows as the input size n grows — and provides a basis for computing and measuring efficiency; it does not give a time in seconds, because it deliberately ignores machine speed, language and constant factors. For small n, 1000N is far larger than N², so timing at small n would name the wrong winner; but N² grows faster, and beyond N = 1000 it overtakes 1000N and keeps pulling away. The correct comparison is therefore of growth rates, not of seconds on one machine with one input — the actual seconds are a matter for posterior analysis.

**15.**
```
Declare and initialize variables
Loop until the user enters sentinel value
    prompt user to enter a number
    allow user to type in a number
    compare the number with the maximum
    add 1 to a counter
Identify maximum number and output result
```
It uses **sequence** (the declared order of the steps, no step skipped), **repetition** (the loop that runs until the sentinel value is entered) and **selection** (the comparison of each number with the current maximum, which updates the maximum only if the condition holds).
