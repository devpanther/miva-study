# Wednesday — COS_102 nightly check

*The eleven computational approaches: what each one is, the condition or caveat attached to it, and what distinguishes it from its neighbour.*
*Sit cold, notes closed, 8 minutes. Score out of 6.*

**1.** Two programs search for the way out of a maze. **Program A** lists every possible sequence of turns of length 20 and runs each one from the entrance until one reaches the exit. **Program B** takes a corridor, recursively takes the next corridor, and when it arrives at a state that is rejected it returns to the junction it came from and takes a turning it has not yet considered. Which names both correctly?
a) Both are brute force; B is simply a brute-force search written recursively
b) A is brute force — it goes through all possible choices, relying solely on computing power — and B is backtracking, which decides which option to follow at each step, tests acceptance at a final state, and returns to a previous state to try unconsidered options
c) A is backtracking, because it tries one sequence and then another, and B is divide and conquer, because the maze is split into corridors solved one at a time
d) A is brute force and B is dynamic programming, because B stores the junctions it has already visited so that it never has to compute them again

**2.** A student writes `fib(n)` as `fib(n-1) + fib(n-2)`, with `fib(0) = 0` and `fib(1) = 1`. It is correct but slow. He then rewrites it so that each value, once computed, is written into a table and read back from there whenever it is needed again. Which is correct?
a) The first version is divide and conquer and the second is dynamic programming, because the second saves the sub-problems' solutions so there is no need to compute the result again
b) Both versions are dynamic programming, because both break the problem into the sub-problems `fib(n-1)` and `fib(n-2)`
c) The first is dynamic programming because it uses recursion, and the second is divide and conquer because it splits the work into a table of easier parts
d) The second is a greedy algorithm, because at each stage it applies the best possible solution — reading the stored value rather than recomputing it

**3.** A student writes: "Greedy algorithms select the best optimal path at every stage, so a greedy algorithm always returns the optimal solution; that is why greedy solutions are simple and highly efficient." Judged against the course, which is correct?
a) The claim is right, and it is dynamic programming that carries no guarantee, since dynamic programming only saves results and never chooses between them
b) The claim is wrong: greedy algorithms never produce optimal solutions, which is precisely why they are simple and fast
c) The claim is wrong: greedy applies the best possible solution at each stage and aims at the optimal solution, but might not always produce one; the guarantee — that provided a solution exists, an optimal solution can be found — belongs to dynamic programming
d) The claim is wrong, because greedy is optimal only when the smaller parts are simpler than the complex part and combining them is the cheaper operation

**4.** An engineer is asked to produce an algorithm that optimises the power-cable infrastructure of a building. Before writing anything, she establishes the parameters of the problem, states the criterion for success, notes that it belongs to a known type, and restates the whole task as "find the minimum spanning tree of this graph". Which is correct?
a) This is visualisation: the building has been redrawn as a graph so that a diagram can illustrate what the problem entails
b) This is divide and conquer: the building has been split into smaller, easier parts — the individual cable runs — each of which is solved separately
c) This is problem recognition, and the final step is the course's move of reducing the problem to a more general case, done so that the solution addresses the root cause rather than a symptom
d) This is data mining, because underlying relationships within the building's wiring data have been discovered and expressed as a graph

**5. (explain why)** A program calculates the total cost of an order by first adding up the cost of the products, then computing the VAT on that subtotal, then adding the two. A second program sorts a list by merge sort. Both "break a task into smaller parts". Name the approach each one is, state exactly what the parts are in each case and how they relate to one another, and give the condition that divide and conquer must satisfy and pipelining need not.

**6. (explain why)** A researcher tests whether a medicine reduces the chance of heart arrest. She fixes a significance level of 0.05 and obtains a p-value of 0.03. State her null hypothesis, state the decision she must make and why, explain precisely what the significance level 0.05 means, and explain what her result does **not** establish.

## Answers

**1. b** — *Brute force explores all choices; backtracking abandons a state and resumes from a previous one.* Brute force "solves a problem by going through all possible choices until a solution is found" and "relies solely on computing power", which is Program A exactly: 20 turns enumerated in advance, nothing pruned, nothing abandoned. Backtracking "involves examining more than one possible solution", uses **recursion to move from one problem state to another**, considers the options at every step and makes a decision about which to follow, and on reaching a **final state checks whether it is accepted or rejected and then backtracks to a previous state to try other unconsidered options** — Program B, and the maze is the course's own illustration. (a) is the answer that catches the student who has learned only "both look at many possibilities": recursion is not what makes B different, the accept/reject test at a final state and the return to an earlier state are. (c) simply swaps the two labels and then misnames a corridor-by-corridor walk as divide and conquer — divide and conquer produces smaller versions of the *same* problem that are solved and then **combined**, and B combines nothing. (d) is the plausible-sounding trap: remembering visited junctions is not dynamic programming, which is defined by **saving the solutions of sub-problems** so the result need not be recomputed; B saves no solution, it only retreats.

**2. a** — *Dynamic programming is divide-and-conquer decomposition plus stored sub-solutions.* Both versions decompose `fib(n)` into `fib(n-1)` and `fib(n-2)`, so decomposition cannot be what separates them — which is why (b) is the most-chosen wrong answer. The course defines dynamic programming as breaking problems into sub-problems **and saving the solutions of the sub-problems so that there is no need to compute the result again**; the table is that saving, and it is the only new thing in version two. (c) inverts both labels and mistakes recursion for the criterion — recursion is mentioned in the course under **backtracking**, not dynamic programming. (d) misapplies greedy: greedy is about choosing the **best option among competing choices at each stage** in order to reach an optimal solution, and reading a stored value is not a choice between candidate solutions at all.

**3. c** — *Greedy aims at optimality; only dynamic programming is said to guarantee it.* The course states both halves carefully: greedy "might not always produce an optimal solution **but** they produce an optimal solution to many problems", and "for problems where the greedy algorithm is able to provide optimal solutions, those solutions are always simple and highly efficient" — so the efficiency claim is conditional on greedy having succeeded, and cannot be used as evidence that it always succeeds. Dynamic programming is the approach of which the course says: **provided that a solution to the problem exists, an optimal solution can be found**. (a) is the reversal of the two guarantees and is tempting because dynamic programming *sounds* passive next to greedy's "best optimal path". (b) overcorrects into a second false absolute — greedy does produce optimal solutions to many problems. (d) is the right verdict supported by the **wrong approach's condition**: "the smaller parts must be simpler than the complex part, and combining them must be the cheaper operation" is the effectiveness condition of **divide and conquer**, and it says nothing about greedy.

**4. c** — *Problem recognition, and the reduction to a more general case.* Problem recognition is defined by exactly the four moves she made: identify the **nature and parameters** of the problem, specify the **requirement or criteria for success**, determine whether the problem can be **grouped as a specific type**, and explore **reducing the problem to a more general case** — and the course's illustration of that last move is this very example, the cable-optimisation task becoming a **minimum spanning tree**. Its purpose is to ensure the proposed solution deals with the **root cause**. (a) is the answer that catches anyone who sees the word "graph" and thinks pictures: visualisation exists to help **humans rather than computers** understand a problem through diagrams, whereas here the graph is the formal object the algorithm will run on. (b) mislabels a change of representation as a decomposition — nothing has been split, and no sub-solutions will be combined. (d) borrows data mining's wording, but no large data set has been searched for unnoticed patterns; the structure was recognised, not discovered in data.

**5.** *Concept: pipelining versus divide and conquer.* The order-total program is **pipelining**: the task is divided into a **series of subtasks in which each subtask leads to the next**, each executed by a **different process in a series**, and **the result of one process feeds into the next** until the whole task is complete — sum the product costs, feed that subtotal into the VAT calculation, feed both into the addition. The parts are **different in kind** from one another and **ordered**: stage two cannot start until stage one has produced its output, and there is no combining step at the end, only a final stage. Merge sort is **divide and conquer**: the complex problem is **split into smaller, easier parts** which are **smaller instances of the same problem** — sorting a list becomes sorting two shorter lists — solved **independently of one another** and then **combined** (merged) into the solution of the whole. The condition divide and conquer must satisfy, and pipelining need not, is the effectiveness condition: the **smaller parts must actually be simpler than the complex whole**, and the **combining of their solutions must be less complicated than solving the original problem directly**. If the merge cost as much as sorting from scratch, the split would buy nothing. Pipelining has no such requirement because its stages are not attempts at the whole problem and their outputs are never recombined — each merely hands its result to the next.

**6.** *Concept: the null hypothesis, significance level and p-value.* Her **hypothesis** is the tentative, intelligent guess that consumption of the medicine reduces the chance of heart arrest; the **null hypothesis** is the assumption of no effect — **that consumption of the medicine does not reduce the chance of heart arrest** (the course's own worked example). The rule is that **when the p-value is less than or equal to the significance level, the null hypothesis is rejected**, and 0.03 ≤ 0.05, so she **rejects the null hypothesis**; the p-value describes **how likely it is that the null hypothesis is true**, and the smaller it is, the stronger the evidence for rejecting it. The **significance level of 0.05 is the probability of rejecting the null hypothesis when it is in fact true** — that is, a **5% risk of concluding that something exists when it does not exist**; it is chosen before the data are seen, which is what makes the comparison meaningful rather than a decision taken after the fact. What the result does **not** establish is proof: the test moves evidence, not certainty. Rejecting the null does not demonstrate that the medicine works in every patient or by any particular mechanism, only that under a 5% error allowance the no-effect assumption does not survive this data; equally, had p come out above 0.05, accepting the null would not have shown the medicine does nothing — as the course puts it, it **just means the evidence is not enough**. A 5% significance level also means that roughly one such rejection in twenty would occur even if the medicine were inert.
