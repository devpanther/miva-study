    In Summary

This week, you learned about transformers—essential devices in power distribution. They convert high
voltage, low current to low voltage, and high current, comprising a primary coil, secondary coil, and iron core.
Operating on mutual inductance, the primary coil’s alternating voltage creates a magnetic field, inducing
voltage in the secondary coil. The transformer equation links input and output voltages to coil turns. In an ideal
scenario, both coils would have equal power, but real-world losses, such as heat, hysteresis, and mechanical
losses, exist. Understanding these losses is crucial for designing efficient transformers, optimising energy
transfer in power systems.



    Bullet point summary

•    They consist of primary and secondary coils with an iron core.
•    Transformers operate on the principle of mutual inductance.
•    Turn ratios determine whether a transformer is a “step-up” or “step-down” transformer.
•    The transformer equation relates input and output voltages to the number of turns in the coils.
•    Power in the primary coil should equal that in the secondary coil in an ideal scenario.
•    Energy losses in real-world transformers include heat, hysteresis, and mechanical losses.

Software testing
Software testing can be explained as a process to ﬁnd out if the output the computer
is giving is the same as the expected output.
How can we tell if the computer is giving the right output or not? A functional test?
Software testing
With software testing, we can locate errors in our program and also, conﬁrm if there
any missing requirements in the program.
The software testing process can either be carried out manually or with automated
tools.
Software testing life cycle
We need a software testing life cycle so that while trying to test our programs, we follow well
deﬁned procedures to be sure that our software meets the set requirements and that it does not
have defects. If there is no standard process like the software testing life cycle, which clearly
deﬁnes the deliverables and objectives of each testing phase, we might not be sure that we are
testing our software the right way.
Software testing life cycle: phases

The software testing life cycle has six main
phases.
These phases in sequential order are the:
•   Requirement analysis phase
•   Test planning phase
•   Test case development phase
•   Test environment setup phase
•   Test execution phase
•   Test cycle closure phase.
Software testing life cycle: phases

Each phase has entry and exit points.
The entry point is where the phase begins and the exit point is where the phase ends,
and all the objectives of the phase have been achieved.
Requirement phase
This is the phase where we decide on what is to be tested.
The requirement phase includes activities such as a software requirement document
review, stakeholders interview and the identiﬁcation of the possible issues that might
aect the software testing process.
Test planning phase
In this phase, the testing strategy, cost and duration are clearly deﬁned.
The test planning phase includes activities such as the identiﬁcation of testing
objectives, testing environment, test cases, and test deliverables.
The assignment of roles to team members also takes place in this phase.
Test case development phase

In this phase, the test cases are clearly deﬁned. So, what is a test case?
A test case gives detailed step-by-step instructions on how a test should be
performed. A test case speciﬁes the test inputs, process and expected outputs.
The test case development phase includes
activities such as the identiﬁcation,
writing, and review of test cases.
Test environment setup phase

In this phase, the software and hardware requirements for the test are speciﬁed.
The test environment setup phase includes activities such as the test data and
environment setup.
Test execution phase

In this phase, the actual software testing takes place, using the test plans and
cases developed in the earlier phases.
The test execution phase includes activities such as test implementation,
retesting to ﬁx defects, test results analysis, and reporting.
Test cycle closure phase

In this ﬁnal phase, checks are carried out to ensure that the testing objectives have
been achieved and that the software is ready for use.
The test cycle closure phase includes activities such as defect identiﬁcation and
correction, summary report creation
and feedback collection.

or incorrect results.
The process of identifying and resolving errors, or bugs, in a software system.

JEREMIAH O. BANDELE

Software testing methods
All the testing methods we are going to discuss can be classiﬁed into two types.
The types are functional and non-functional testing methods.
Functional testing
Functional testing methods are the testing methods used to test the computer
program to ensure that the program performs as expected, such as testing
if an addition function works as expected.
Some of the functional testing methods are unit testing, integration testing,
acceptance testing and system testing.
Unit testing
Unit testing is a type of testing where test data is used to check the execution paths in a
software to be sure that they are working as expected.
Unit tests are mostly carried out on the functions in the program.
A limitation to this method is that it is practically
impossible to test all the execution paths in a
software. Also, the number and type of test data
we can use for the testing is limited.
Integration testing
Integration tests are used to test how well dierent parts of a software work together.
Integration tests can either be top-down or boom-up.
With the top-down approach, higher-level modules are tested ﬁrst before the lower-level
modules are tested.
With the boom-up approach, lower-level
modules are tested ﬁrst before the
higher-level modules are tested.
System testing
System tests are used to test the system as a whole after all the parts are integrated,
to conﬁrm that the system is working as expected.
System tests are used to conﬁrm that the software meets the technical and
functional requirements.
Acceptance testing
Acceptance tests are also used to conﬁrm that the software meets the expected requirements.
In addition to testing for issues such as spelling errors, acceptance tests are used to identify bugs
that can cause major errors and software crashes.
Non-functional testing
Non-functional methods are used to test the non-functional aspects of a software
such as the user interface. These tests are also used to ensure that the software
is secure enough.
Some of the non-functional testing methods are usability testing,
performance testing, security testing and compatibility testing.
Usability testing
Usability tests are used to discover any issues with the software with the help of users.
The users are observed while using the software and all the performance issues they
face are identiﬁed and addressed.
Performance testing
Performance tests are used to discover performance issues such as network
delays, database and client-side processing.
Performance tests are also used to check how the software will perform under
dierent load conditions.
Security testing
Security tests are used to discover any vulnerability or security ﬂaw in the software.
Security tests are used to check for issues such as data security, software
availability, conﬁdentiality and integrity.
Compatibility testing
Compatibility tests are used to determine how compatible a software is with
dierent environments such as dierent browsers, platforms and operating systems.
Compatibility test are used to ensure that the software can perform as expected
across all the possible environment that the end users will use the software in.
Other testing methods
Some other testing methods are:
•   Black box testing
•   White box testing
•   Grey box testing
Black box testing
A software testing method in which the internal structure/design/implementation of the
item being tested is not known to the tester. These tests can be functional or
non-functional, though usually functional.
This method is named so because the software program,
in the eyes of the tester, is like a black box,
inside which one cannot see.
Applicable to integration testing,
system testing and acceptance testing.
Black box testing: example
A tester, without knowledge of the internal structures of a website, tests the web
pages by using a browser; providing inputs (clicks, keystrokes) and verifying
the outputs against the expected outcome.
White box testing
A software testing method in which the internal structure/design/implementation
of the item being tested is known to the tester.
The tester chooses inputs to exercise paths through the code
and determines the appropriate outputs.
Programming know-how and the implementation
knowledge is essential.
White box testing is testing beyond the user interface.
Applicable to unit testing, integration testing,
and system testing
White box testing: example
A tester, usually a developer, studies the implementation code of a certain
ﬁeld on a webpage, determines all legal (valid and invalid) AND illegal inputs
and veriﬁes the outputs against the expected outcomes,
which is also determined by studying the implementation code.
 Grey box testing

A combination of the black box and white box testing methods,
where the internal structure is partially known.
This involves having access to internal data structures and
algorithms for purposes of designing the test cases, but testing at
the user or black-box level.
Named so because the software program,
in the eyes of the tester is like a
gray/semi-transparent box; inside
which one can partially see.
Primarily used in integration testing.
Grey box testing: example
An example of Gray Box Testing would be when the codes for two units/modules
are studied (White Box Testing method) for designing test cases and actual
tests are conducted using the exposed interfaces (Black box Testing method).

    to conﬁrm that the system is working as expected.
